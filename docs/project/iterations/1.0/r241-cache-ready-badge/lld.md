## 1. 需求拆解

| 需求句 | 拆解 |
| --- | --- |
| 整本翻译 / 整本朗读 / 全文单词详解 都已有缓存 | 三条整本链路的产物分别落在 moon-well 的段落译文缓存、段落音频缓存、单词详解缓存；对一本书而言，「都有缓存」= 三个方向的产物都覆盖了当前这一版正文。 |
| 每个都有一个特殊的标识 | 三项各自一枚标识（哪项备齐亮哪项），三项齐备时再加一枚总标。 |
| 让用户知道这本书可以较为便宜的学习 | 标识面向**普通读者**（不是只有管理员），且必须出现在读者决定「读不读这本书」的界面——书籍详情页（含书卡点开的详情弹层）。 |

## 2. 判定口径（为什么用本仓台账）

`moon-well` 没有任何「按书统计三层缓存覆盖率」的端点：

- 译文：`/reading/paragraph-cache/find-translations`（按段落批量，需先解析整本 EPUB）；
- 详解：`/vocabulary/detail/cached-check`（按词批量，同样需先解析整本 EPUB）；
- 音频：只有逐段的 `/tts/cached-audio` 或 `hasAudio`，**没有批量探测口**（R214 代价面板因此明确「朗读不做缓存探针」）。

也就是说，实时探测一次「这本书三项是否都备齐」= 一次整本 EPUB 解析 + 数十次上游批量调用。把它放在详情页读路径上不可接受（R238 正是为此把详解预览改成后台快照 + 轮询）。

本仓三条链路本来就各有一张执行台账，且其终态语义恰好就是「这一版正文跑满、没有失败」：

| 链路 | 模型 | 终态 | 「跑满」判据 |
| --- | --- | --- | --- |
| 整本翻译 | `reading_translation_job` | `COMPLETED` | `completed_count >= total_count`（缓存命中的段也直接记 COMPLETED） |
| 整本朗读 | `reading_tts_job` | `COMPLETED` | `done_count >= total_count`（只有 pending 清零且 failed=0 才会置 COMPLETED） |
| 全文单词详解 | `reading_word_detail_job` | `COMPLETED` | `covered_words >= target_words`（覆盖数含预览时已命中的词） |

因此标识数据源取**台账**：一次本地 SQLite 查询（3 条），零上游调用、零 EPUB 解析，详情页与详情弹层都能直出。

### 2.1 必须同时满足的四个约束

1. `status == COMPLETED`；
2. `total > 0`（`total == 0` 只说明没跑成，不代表缓存里有内容）；
3. `book_fingerprint` 与当前文件指纹一致（书被替换/重排后旧批次不再代表这一版）；
4. `book_format` 与展示格式一致（kepub 批次不给 epub 背书）。

任一不满足即该项不亮；更早的 `COMPLETED` 行若满足条件仍可回退命中（不被更新的脏行一票否决）。

## 3. 已知边界（明确不承诺的事）

- **不是实时探测**：缓存事后被上游清掉时标识会滞后。三条链路的缓存本身是加速器（moon-well 段落缓存读失败按 miss 降级），真正开跑仍以缓存实况为准并会自愈；标识只承诺「这一版跑过且跑满了」。
- **依赖台账的终态收敛（重要）**：整本翻译与全文详解的 `COMPLETED` 不是后台线程自己收敛的——moon-well 写完缓存不会回调本仓，只有整本任务面板 / 批量进度页**轮询进度**时才会做缓存懒回收并把状态推到 `COMPLETED`（R78 起的既有设计：不引入常驻轮询进程）。朗读链路的 worker 自己会置 `COMPLETED`，不受影响。
  - 实际影响：管理员点完「开始」就立刻关页面、且之后再不打开该书/该进度的，翻译与详解两项标识会一直不亮，直到下一次有人打开面板触发收敛。
  - 这是本功能的**已知滞后**，不额外引入轮询线程（会与 R78 的去回调化设计相违）；排查时先看该书最新批次的 `status`。
  - 用例 `test_published_but_not_converged_is_not_ready` 把这个边界显式钉住。
- **只认本仓发起过的批次**：若三项缓存完全由其他路径积累（例如读者逐段翻译、MagicLens 逐词查询），没有整本批次就不会亮。这类书要亮标需管理员跑一次对应整本任务——成本极低（全部命中缓存，秒级完成）。
- **查询失败不亮、不报错**：台账表缺失、库忙、文件不可读都只让标识缺席，绝不把详情页打成 500（与 R214 `active_jobs`、R238 预览快照同一纪律）。
- **归档书**：`show_book` 允许看归档书详情，但 `_book_file` 的取书口径不含归档书，因此归档书不会亮标（静默不出，不报错）。
- **详解的 n/m 口径**：台账的分母 `target_words` 是「本次补缺词数」（预览时已缓存的词不进分母），因此悬停文案改用 `distinct_words`（全书去重词数）表述，避免「200/200 词」被误读成全书只有 200 词。
- **不替代代价面板**：整本任务面板仍按需实时估算覆盖率与积分（`/ajax/whole-book-estimate`）。两者口径不同且互补：面板回答「现在还要花多少」，标识回答「以前是否已经备齐过」。

## 5. 文案与计费口径

| 标识 | 文案 | 悬浮说明 |
| --- | --- | --- |
| 总标 | 低成本学习 | 整本翻译、整本朗读、全文单词详解三层缓存都已备齐，学习这本书更省积分 |
| 分项 | 整本翻译已缓存 | 已备齐（n/m 段），命中缓存不额外计费 |
| 分项 | 整本朗读已缓存 | 音频已备齐（n/m 段），播放命中缓存按 1 积分/段计（moon-well R213 口径） |
| 分项 | 全文详解已缓存 | 已备齐（n/m 词），查词命中缓存不再生成 |

## 6. 验收要点

1. 三项都跑满的书：详情页出现「低成本学习」+ 三枚分项芯片，计数正确。
2. 只跑满一两项：只亮对应分项，不出现总标。
3. 书文件被替换（指纹变化）：标识全部消失（旧批次不冒充新版本）。
4. 从未跑过整本任务的新书：无任何标识，页面无报错。
5. 普通读者账号（非管理员）也能看到标识；整本任务按钮仍只对管理员可见（R214 拍板①不变）。
6. 台账查询故障时：详情页正常渲染，仅缺标识。
