# R273 LLD · 登录页改用邮箱验证认领账号

## 1. 为什么要改

R272 的第二入口是「我已有账号，用密码绑定」：先换票据，再输网页端账号密码。
它有两个问题：

1. **密码是额外的记忆负担**——用户可能忘了，可能当初是 OIDC 建号根本没设过密码（50405）；
2. 账号本来就有邮箱，邮箱才是他日常用来认领账号的东西。

R241 在后端补了「未登录态邮箱验证」，本次把界面换过来。

## 2. 状态机

```
idle ──点「微信一键登录」──────────────→ 自动建号 → 主界面
  │
  └──点「我已有账号，用邮箱登录」
        ↓ auth.login(true)  只拿 10 分钟票据，不建号
      email ──发码──────────────→ code ──验码──→ 主界面
        │                            │
        └──返回───────────────┘     └──50514/50403 → 回 idle（带提示）
```

三个状态各自对应一张卡片，都在登录页内展开：票据 10 分钟过期，多一次跳转就多一个失败面。

## 3. 关键实现点

| 点 | 做法 | 为什么 |
|---|---|---|
| 不建号 | `auth.login(true)` | 邮箱入口若走自动建号，用户会先得到一个空账号，再被归并——多一次无谓的写入，且中途放弃就留下垃圾 |
| 倒计时 | 取后端 `resendAfter` | 前后端各写一个 60 秒，改了一边就错位，「点了没反应」最难查 |
| 50514 | 回 `idle` + 明确文案 | 这不是错误输入，是「你还没账号」；原地重试永远失败 |
| 50403 | 回 `idle` | 票据废了还留着表单，用户每点一次都得到同一个错 |
| 密码框 | 整段删除 | 界面留着就是邀请用户去用一条更差的路 |

## 4. 后端端点保留说明

`/auth/wx/bind`（密码认领）**没有删**，只是界面不再暴露。原因：存量账号里有 3 个没有邮箱，
它们无法走邮箱认领；将来若需要给这类用户一条自助路径，端点还在，不必再发一次版。

## 5. 部署顺序

先 moon-well R241（含 `sql/r241-email-scope.sql`），再发小程序。
旧后端没有 `/auth/wx/email/*`，点了会 404 —— 而小程序有审核周期，先发后端天然安全。

## 6. 未做

- 邮箱表单没有做键盘避让的专门处理（原生 input 自带 focus 上推，真机需确认遮挡情况）。
- 没有「换个邮箱重试」按钮：返回 + 重新点入口即可，票据会换新的。
- 不支持在登录页直接注册（新用户走微信一键登录）。
