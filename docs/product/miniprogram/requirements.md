## 1. 模块范围

微信小程序里的三页工具：每日复习、词汇量测试、「我」（账号 + 学习数据），
以及它们直连 moon-well 的鉴权与请求层。（R292 起；此前含第四页「AI 伴读通用对话」。）

不含：书库 / 阅读器 / 翻译 / 朗读 / 网页端生词本（都在网页端 `magicbook.haoshenqi.top`）；
任何形态的 AI 伴读——书内抽屉与通用对话都只在网页端与浏览器扩展
（归 [companion 模块](../companion/requirements.md)）。

## 2. 需求条目

### R280 AI 伴读（对话）接入小程序，加载通用对话 prompt，生词本功能下掉（AI 伴读部分已被 R292 取代）

> **R292 注（2026-11-11）**：本条的 AI 伴读部分（下列第 1–6、8 点及验收待办）已被 R292 取代——
> 对话页整体移除。「生词本下掉」（第 7 点）与「兼容老客户端」（第 9 点）仍然有效。历史原文保留不改写。

- **来源**：用户 2026-11-04 原话「微信小程序接入AI伴读（对话）功能，加载通用对话prompt。生词本功能下掉。」
- **口径确认（用户拍板，2026-11-04）**：
  1. 现网没有名为「通用对话」的 prompt（只有书内 `agent-chat-system` 与网页 `agent-chat-system-web`）
     → **新建** `agent-chat-system-general`，不复用、不改老的两套；
  2. 「生词本功能下掉」→ **删页面并换伴读 tab**，不是隐藏入口、不是只改文案；
  3. 对话形态 → **复用现网 `POST /ai/agent/chat` 的 SSE 流式**，不新增接口。
- **跨仓**：moon-well R243 提供 `scene=general` 分支与新 prompt；部署顺序**先后端、再小程序**。

**应该长什么样**：

> **R283 注（2026-11-05）**：本条第 1 点里的 tab 文案「伴读」已被 R283 改为「AI」；
> 功能名「AI 伴读」、页面标题与对话契约不变。历史原文保留不改写。

1. **能在小程序里对话**：tab「伴读」可直接发问，回答逐字出现；有欢迎语与快捷问题降低首次使用门槛。
2. **不假设阅读上下文**：小程序里没有书也没有网页正文。请求不得携带书页字段，
   系统提示词不得提书名、章节、页码，也不得编造「当前页原文」；想就书提问仍去网页端。
3. **通用对话 ≠ 把书内 prompt 删空**：仍保留长期记忆与用户自我介绍，能聊英语学习
   （词义 / 语法 / 表达 / 读书方法 / 学习计划）也能自然闲聊。
4. **工具要跟着场景收窄**：依赖书页的工具（批注、段落译文）在通用场景不可用；
   通用查词等无上下文工具仍可用。
5. **闲聊默认不写长期记忆**：`skipMemoryExtract: true`；用户明确要求「记住」时才沉淀。
6. **会话可续**：`conversationId` 本地保存并回传；「新会话」只清界面与本地 id，不删服务端历史。
7. **生词本下掉后不丢能力**：微信临时账号的绑定提示必须迁到仍存在的页面；
   词汇量测试里「收进生词本」文案要指明是**网页端**生词本，不制造小程序里不存在的入口。
8. **失败可见**：白名单 / 超时 / 链路错误保留原始 `errMsg` 并给出下一步动作，
   不抹成「请检查网络」，也不静默降级成「暂无数据」。
9. **兼容老客户端**：不传 `scene` 的网页端与 magiclens 插件保持原有书内 / 网页分支，行为不变。

**验收待办**：体验版 `1.0.1` 已上传（2026-11-05，R283 重传）；在后台选为体验版后，
真机核对 `enableChunked` / `onChunkReceived` 的流式表现（首字到达、中文不乱码、
切后台返回）、以及新 AppID 的 request 合法域名。

### R290 缺陷修复：每日复习页的卡片必须有题面

- **来源**：用户 2026-11-08 15:36 截图报障「修复这个小程序的bug」——卡片区只有一句
  「看下面的提示，回想这个词」和「揭示答案」，没有任何可回想的内容。
- **根因**：题干只在「四选一 / 拼写」两个分支渲染，`RECALL` 被降成 `SELF` 后落进一句提示语；
  释义缺失时提示语、释义、词面三者全不出现，卡片是白板。
- **应该长什么样**：
  1. **有释义就出题干**——`RECALL` 的题干就是中文释义，与四选一/拼写同源；
     语境挖空句（`CONTEXT_CLOZE`）用它当题干；
  2. **没释义也不出空卡**——直接亮出英文词，按「忘记 / 很难 / 想起 / 轻松」自评；
  3. **揭示前不泄题**——词面与语境原句（含目标词）只在揭示后出现，`SELF` 除外；
  4. **拼写卡也能揭示**——想不起来的人必须走得掉；
  5. 作答回传的 `questionType` 仍是后端原值，不随本地呈现态改变（调度口径不变）。
- **不做**：不补生成释义（只读缓存，避免消耗积分）、不改后端题型策略、不动统计卡与完成态。

### R292 移除 AI 伴读能力（微信上架合规）

- **来源**：用户 2026-11-11 原话「移除小程序的AI能力，否则无法上架」。
- **取代**：R280 的 AI 伴读部分与 R283 全部。
- **应该长什么样**：
  1. **代码包里没有 AI**——对话页目录、页面注册、tabBar 项、请求层的流式对话通道与对话专用超时
     全部删除；不接受「只藏入口、代码留着」，审核看的是代码包；
  2. **底栏三项**「复习 / 词汇量 / 我」，默认仍落「复习」；
  3. **文案不再宣传 AI**——登录页副标题、工程描述、导航标题里不出现 AI 字样；
  4. **其余能力不受影响**——复习、词汇量测试、账号、学习数据的行为与接口不变；
  5. **生词本页不复活**——R280 下掉的生词本保持下掉。
- **不做**：不动 moon-well 的 `/ai/agent/chat`、`scene=general` 分支与 `agent-chat-system-general`
  prompt（网页端与扩展仍在用同一接口，通用 prompt 留着无害）；不删用户已有的服务端会话历史；
  不动网页端与 magiclens 的 AI 伴读。
- **仓外待办（需用户操作）**：小程序后台的名称 / 简介 / 服务类目若写了 AI 相关内容需同步改掉；
  重新上传代码包并提审。
