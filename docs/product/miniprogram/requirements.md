## 1. 模块范围

微信小程序里的四页工具：每日复习、AI 伴读通用对话、词汇量测试、「我」（账号 + 学习数据），
以及它们直连 moon-well 的鉴权与请求层。

不含：书库 / 阅读器 / 翻译 / 朗读 / 网页端生词本（都在网页端 `magicbook.haoshenqi.top`）；
阅读页里的书内 AI 伴读抽屉（归 [companion 模块](../companion/requirements.md)）。

## 2. 需求条目

### R271 工具型小程序四页（已被 R280 部分取代）

- **来源**：2026-11-03「微信小程序：生词本 / 每日复习 / 词汇量测试 / 学习数据」。
- **应该长什么样**：四页 tab，默认落「复习」；账号自动建号、可绑邮箱认领老账号；
  复习与词汇量测试复用网页端同一份数据。
- **已被 R280 取代的部分**：第二个 tab「生词本」及其页面整体下掉，改为「伴读」。
  复习 / 词汇量 / 「我」三页与账号口径不变。

### R280 AI 伴读（对话）接入小程序，加载通用对话 prompt，生词本功能下掉

- **来源**：用户 2026-11-04 原话「微信小程序接入AI伴读（对话）功能，加载通用对话prompt。生词本功能下掉。」
- **口径确认（用户拍板，2026-11-04）**：
  1. 现网没有名为「通用对话」的 prompt（只有书内 `agent-chat-system` 与网页 `agent-chat-system-web`）
     → **新建** `agent-chat-system-general`，不复用、不改老的两套；
  2. 「生词本功能下掉」→ **删页面并换伴读 tab**，不是隐藏入口、不是只改文案；
  3. 对话形态 → **复用现网 `POST /ai/agent/chat` 的 SSE 流式**，不新增接口。
- **跨仓**：moon-well R243 提供 `scene=general` 分支与新 prompt；部署顺序**先后端、再小程序**。

**应该长什么样**：

1. **能在小程序里对话**：tab「伴读」可直接发问，回答逐字出现；有欢迎语与快捷问题降低首次使用门槛。
2. **不假设阅读上下文**：小程序里没有书也没有网页正文。请求不得携带书页字段，
   系统提示词不得提书名、章节、页码，也不得编造「当前页原文」；想就书提问仍去网页端。
3. **通用对话 ≠ 把书内 prompt 删空**：仍保留长期记忆与用户自我介绍，能聊英语学习
   （词义 / 语法 / 表达 / 读书方法 / 学习计划）也能自然闲聊。
4. **工具要跟着场景收窄**：依赖书页的工具（批注、段落译文）在通用场景不可用；
   通用查词等无上下文工具仍可用。
5. **闲聊默认不写长期记忆**：`skipMemoryExtract: true`；用户明确要求「记住」时才沉淀。
6. **会话可续**：`conversationId` 本地保存并回传；「新会话」只清界面与本地 id，不删服务端历史。
7. **生词本下掉后不丢能力**：微信临时账号的绑定提示必须迁到仍存在的页面；
   词汇量测试里「收进生词本」文案要指明是**网页端**生词本，不制造小程序里不存在的入口。
8. **失败可见**：白名单 / 超时 / 链路错误保留原始 `errMsg` 并给出下一步动作，
   不抹成「请检查网络」，也不静默降级成「暂无数据」。
9. **兼容老客户端**：不传 `scene` 的网页端与 magiclens 插件保持原有书内 / 网页分支，行为不变。

**验收待办**：体验版 `1.0.0` 已上传（2026-11-05 11:35）；在后台选为体验版后，
真机核对 `enableChunked` / `onChunkReceived` 的流式表现（首字到达、中文不乱码、
切后台返回）、以及新 AppID 的 request 合法域名。
