# vocabulary 模块（词汇学习）· 需求基线

> 本文件是 vocabulary 模块的需求基线（静态：这个模块「应该」长什么样）。
> 需求台账见 [`../../project/requests/requests.md`](../../project/requests/requests.md)；
> 用户手册见 [`../readme/vocabulary.md`](../readme/vocabulary.md)；
> 接口与实现边界见 [`interface.md`](./interface.md) 与 [`features/`](./features/)。
> 建立：2026-10-28（R238 定稿时补建）。既有 R176 全文详解需求不回溯重写，仍以其 L2/L3/历史设计为准。

## 1. 模块范围

生词判定、认识/生词标记、生词本、词汇量测试与难度档位，以及按书补缺的全文单词详解。

划词气泡、网页生词高亮与单词详解面板的交互入口由 MagicLens 扩展承接；moon-well 是判定矩阵、词族口径、测试状态机与详解缓存语义的后端权威。

## 2. 需求条目

### R238 全文单词详解预览可在后台计算且失败可见

- **来源**：用户 2026-10-28 原话「magicbook 全文单词详解 卡在预览加载中。booi_id=145 这是为什么？所有的书是否都会这样？能否加一个异步任务，后天提前把这个算出来」。“后天”按“后台”理解。
- **问题（现状事实）**：预览页的内联脚本放在 `block body`，早于 layout 底部的 jQuery 执行，浏览器以 `$ is not defined` 中断；`/ajax/word-detail-preview` 请求从未发出，页面对所有书都停在「预览加载中…」。即使修好脚本，同步预览仍会在请求线程解析整本 EPUB，并串行做多轮全索引缓存扫描。

**应该长什么样**：

1. **所有书共用同一正确启动路径**：页面脚本在 jQuery 之后执行；`book_id=145` 与任意 EPUB/KEPUB 书都走同一预览接口，不存在单书特判。
2. **后台计算而非请求线程干等**：首次预览返回 `RUNNING` 并显示阶段与已检查词数；计算完成后页面自动切换到数字、缺失词样例和可用的开始按钮。
3. **快照复用**：同一本书 10 分钟内的 `READY` 预览直接返回；正文指纹变化后旧快照自动失效；`force=true` 可主动重算。
4. **失败可见且有退避**：上游不可达、授权失效或解析失败时状态为 `FAILED`，页面显示真实原因；60 秒内不因页面轮询反复重试。
5. **预览仍然只读**：只查详解缓存覆盖率，绝不自动生成详解；真正入队仍需管理员确认并点击“开始补缺”。
6. **开始不重复扫描**：预览刚完成后立即开始补缺时，允许复用同一指纹的 READY 快照中的词表与计数。

**边界**：

- 不为“提前算好”对全库书籍批量预热；只有实际打开某本书的预览页才触发该书后台计算。
- 不在本轮修改 moon-well 的 `cachedLookupKeys()` 全索引扫描实现；跨仓检索优化另立任务。
- 预览快照按 `(book_id, book_format)` 保存，不含用户私有数据。

**验收要点**：任意管理员打开一本书不再出现 `$ is not defined`，首屏可见后台阶段，完成后自动出数字；同一本书刷新命中快照；上游失败有可见文案；开始补缺复用新鲜快照且不重复探缓存；预览路径始终不调用生成端点。

### R239 预览覆盖率采用后端同一套屈折命中口径

- **来源**：用户 2026-10-28 对 R238 预览结果的修订意见——「这个计算不对，完全没有考虑曲折变形」，其中“曲折”按“屈折”理解。
- **问题（现状事实）**：R238 的后台计算本身正常，但 moon-well `cached-check` 扫描缓存时只投影
  `forms.form`、漏掉判定所需的 `forms.type`，导致 `books / children / going` 等词形全被列为
  缺失。扫描是全局词库视图，因此所有含屈折形式的书都会被高估待生成量。

**应该长什么样**：

1. **同一命中口径**：moon-well 已有的词目文档覆盖其七类屈折形式；`books` 命中 `book` 文档即算
   已缓存，派生词仍按自身词条计算。
2. **后台结果采用修正值**：moon-well R226 上线后，magicbook 新计算或 `force=true` 刷新的
   READY 快照必须返回修正后的 `cachedWords / targetWords / missingSample`。
3. **不在消费方复制词形算法**：magicbook 继续照抽不滤，覆盖率语义只由 moon-well 提供，避免
   两仓词形集合再次漂移。
4. **只读边界不变**：预览仍只调用 `cached-check`，不自动生成、不产生 token 费用。

**边界**：

- 本仓不需要改预览 worker 代码；修复主责在 moon-well R226。
- READY 快照有 10 分钟 TTL，上游算法刚上线时可能短暂保留旧数字；验收用 `force=true` 强制刷新。
- 不在 magicbook 侧按后缀或词典自行判断屈折，否则会与 moon-well 的七类白名单分叉。

**验收要点**：`book_id=145` 强制刷新后，`books / children / going / beasts / witches / revolting`
移出 `missingSample`，`cachedWords` 上升、`targetWords` 下降；预览路径仍没有生成端点调用。
