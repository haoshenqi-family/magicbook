# library 模块（书库 / 首页入口）· 需求基线

> 本文件是 library 模块的**需求基线**（静态：这个模块「应该」长什么样），随每次需求讨论增改；条目带 `R<编号>` 溯源，被取代的旧条目标注「已被 R<x> 取代」不删除。
> 需求台账（全史编号与一句话）见 [`../../project/requests/requests.md`](../../project/requests/requests.md)；PingCode idea 见 Ship 需求池（MAGICBOOK 产品）。
> 建立：2026-10-23（R213 讨论定稿时补建；此前 library 无基线文件，R211–R216 六条体验需求只落到台账 + PingCode，随各单设计阶段补齐）。
> 2026-10-23 补 R214 条目（MB-13 讨论定稿）。

## 1. 模块范围

首页入口与书库浏览侧：登录后第一屏（信息架构）、书架侧边栏、书库列表与筛选、搜索入口、书籍详情页的信息组织。阅读器内部交互归 [reading 模块](../reading/interface.md)，学习中枢归 [learning 模块](../learning/requirements.md)。

## 2. 需求条目

### R213 首页信息架构：继续阅读 / 今日计划 / 分级推荐 + 侧边栏分组 + 移动端底部导航

- **来源**：首访体验 QA 报告 §三.2–3.6、§八（`docs/project/qa/2026-10-23/2026-10-23-qa-report.md`，截图 `i1-home-zh.png` / `96-entered.png` / `f1-mobile-home.png`）
- **PingCode**：Ship idea MAGICBOOK-220（Planned）· PJM 工作项 MB-12（用户故事，迭代 1.0）
- **问题（现状事实）**：首页＝「发现（随机四本）+ TED 视频」，无继续阅读、无今日计划、无分级推荐；侧边栏 10 个书架平铺（TED 108 本与分级阶1 的 2 本同级），底部「创建书架」在 900px 视口被裁掉一半；11 个筛选 chips 只有图标无文字；TED 视频卡与电子书卡外观一致；搜索与高级搜索并排重复；移动端无底部导航、无「我的书架 / 继续阅读」。

**应该长什么样**（六条，2026-10-23 定稿）：

1. **首页三模块**：继续阅读（最近在读的书 + 进度，可「回到 37/125」）/ 今日计划（待复习词数 + 写作待办）/ 分级推荐（按难度阶 × 未读规则化推荐）。随机发现降为其中一个模块，不再独占首屏。
2. **侧边栏分组**：书架（用户自建）/ 分级（阶 1..N）/ 媒体（TED 音视频）/ 系统，每组显示计数；「创建书架」按钮在 900px 高度可视口内完整可见。
3. **筛选 chips 补文字标签**：11 个图标 chip 均带文字；窄屏收进「筛选」抽屉，图标单独出现时必须有 tooltip。
4. **卡片格式徽标**：每张卡可区分 EPUB / PDF / TED 音频 / 视频时长 / 原声是否已缓存。
5. **搜索入口去重**：顶栏「搜索」与「高级搜索」合并为一个入口 + 高级筛选面板。
6. **移动端底部导航**：书架 / 学习 / 我的 三个一级入口常驻底部，汉堡菜单只留次要项。

**落地口径（2026-10-23 用户拍板，四问）**：

| 问题 | 拍板 |
| --- | --- |
| 拆单 or 整单 | **拆三单**：A 导航与外壳 / B 继续阅读 / C 今日计划 + 分级推荐（PJM 工作项 MB-16 / MB-17 / MB-18 挂 MB-12 之下） |
| 阅读进度存哪 | **新开 `reading_progress` 表**（不往 `ub.ReadBook` 加列，不与 Kobo 通道共用 `KoboReadingState`） |
| 首页路由 | **新开 `/home`**，`/`（原发现页）保留为回退路径 |
| 今日计划口径 | **暂定「待复习词数 + 写作待办」**；写作待办按 `/ajax/learning/writing/history` 数「今日未完成」（`lastDraftNo == null`），不新建 moon-well 接口 |
| 难度阶来源 | **按书架名解析 `阶N`**（同阶多书架合并，按数字升序）；不新增 Books 字段。**注：2026-10-23 被 R214 §难度扩源**（标签 `阶N` > 书架名 `阶N` > 系列映射 > 未分级），两处共用同一解析器，本条原结论不删、以扩源为准 |
| `/home` 落点 | **直接作为登录后默认落点**（`config_home_landing` 默认 `true`），保留开关回退 |
| 侧边栏四组判定 | **待定**：`shelf` 表无分类字段，方案见 HLD §7.1（建议新增 `shelf.kind` 列）；「系统」组放什么一并待定 |

**非目标**：不做推荐算法 / 协同过滤；不做首页自定义布局（沿用 R208 banner 管理思路另议）；游客浏览属后台配置开关，不在本条改代码。

**待拍板**（阻塞 A 的落地细节，见 HLD §7.1）：侧边栏分组的判定依据（`shelf` 表无分类字段）、「系统」组放什么。

**验收**：① 登录首屏看到「继续读哪本 + 今天要做什么」；② 次日三步内回到 37/125；③ 1440×900 与 390×844 两档无裁切、无横向滚动；④ 每张卡片能区分媒体类型。

### R214 书籍详情：简介 / 目录 / 难度 / 试读 + 整本任务代价面板 + 元数据修正

- **来源**：首访体验 QA 报告 §四（`docs/project/qa/2026-10-23/2026-10-23-qa-report.md`，截图 `a2-book-detail.png`）
- **PingCode**：Ship MAGICBOOK-221 · PJM 工作项 MB-13（用户故事，迭代 1.0）
- **问题（现状事实）**：详情页只有元数据与按钮，回答不了「这本书讲什么 / 难不难 / 值不值得读」——简介空（`detail.html:305` 已有渲染但数据缺）、出版日期显示的是导入时间（Calibre 无 `dc:date` 时以导入时间填 pubdate）、双语书只标 English（`cps/epub.py:84-94` 只取第一条 `dc:language`）、三个整本按钮只有 `confirm` 无任何代价预估不敢点、「已在书架」移除芯片与「加入书架」按钮视觉不可分。**另核出一处更急的缺陷**：`detail.html:80` 一个 `role_admin()` 条件包住整本翻译/朗读/详解与「在线阅读」，R211 后普通读者详情页连阅读入口都没有。

**应该长什么样**（2026-10-23 定稿）：

1. **元数据不伪造**：出版日期与入藏时间相差 ≤1 天 → 显示「导入于 …」；语言只按书目自身声明显示（不猜），导入侧读全 `dc:language`，声明 ≥2 种加「双语」徽标；难度标签四级兜底（标签 `阶N` > 书架名 `阶N` > 系列映射 > 未分级）。
2. **简介三级回退**：书目自带简介（原文无标注）→ AI 生成简介（明确标注「由 AI 生成」）→ 「暂无简介」并指向目录与试读。
3. **目录 + 首章试读**：章节树（含每章段数）+ 首章 ≤1200 字试读，不离开页面先看文风；**不做跳章**（阅读器无定位通道）。
4. **整本任务统一入口 + 代价面板**：三个整本按钮合并为「整本任务」模态（三 Tab 同构代价卡：量 / 不修改原文件 / 覆盖率 / 耗时 / 积分），开始前二次确认，进行中显示进度；进度条必须标明当前任务类型（整本翻译 / 整本朗读 / 全文单词详解）与状态；仅管理员可见。
5. **阅读入口解禁**：「在线阅读」移出 admin 门禁（`role_viewer()`），三个整本入口保留管理员专属。
6. **「已在书架」可分辨**：已加入的书架显示为可移除 chip，与「加入书架」按钮分视觉层级。

**落地口径（2026-10-23 用户拍板，六问）**：

| 问题 | 拍板 |
| --- | --- |
| 整本任务对谁可见 | **仅管理员**；普通读者只保留在线阅读 |
| 积分费率来源 | **moon-well 新增只读费率回传端点**（跨仓占号 R207），magicbook 不镜像常量 |
| 朗读的缓存命中 | **暂不做**批量探针；面板给「全 miss 上限」+「已缓存段不重复计费」说明 |
| 简介缺失怎么办 | **AI 生成**，页面标注「由 AI 生成」；不自动生成，管理员触发 |
| 双语怎么判 | **按书目自身声明**：页面不猜；导入侧 `dc:language` 读全；存量走补正脚本（dry-run 默认） |
| 难度阶数据源 | 与 R213 共用解析器，扩源为「标签 `阶N` > 书架名 `阶N` > 系列映射 > 未分级」 |
| AI 简介要不要「重新生成」按钮 | **不要**（2026-10-23）：已生成即定稿；改写/重生成属未来需求另立 |

**非目标**：不做阅读器章节跳转；不做按正文探测语言；不改三个整本 job 内核；不做书封大图 / 试读分页 / 读者评分评论；三份 EPUB 解析器的收敛记技术债另立一条。

**待拍板**（不阻塞开工）：存量语言补正 dry-run 清单出来后，书虫那批的执行范围。

**验收**：① 普通读者打开详情页能看到「在线阅读」，管理员看到完整工具区；② 简介/目录/试读三块让「讲什么、值不值得读」有答案，AI 简介带标注；③ 点整本任务前能量化看到「多少量、多久、多少积分、不改原文件」；④ 出版日期与语言不再说谎（伪出版日显示为导入、双语标两种语言）；⑤ 三条整本链路运行时，吸顶进度条都明确显示任务类型与当前状态，不能只剩百分比和计数。

**验收缺陷（R247，2026-10-29）**：归档书可由详情页正常打开，但内容速览复用了整本任务默认的取书过滤，误报 `book is unavailable`。修复后内容速览、AI 简介、估算与缓存标识跟随详情页的归档可见性；三条整本任务仍保持原归档过滤。

### R241 整本能力缓存齐备标识：三项缓存都备齐时告诉读者「这本书学起来便宜」

- **来源**：用户 2026-10-28 原话「magicbook 增加一个功能，如果整本翻译，整本朗读，全文单词详解 都已经有缓存了，则每个都有一个特殊的标识，让用户知道这本书可以较为便宜的学习了。」
- **应该长什么样**：书籍详情页（含书卡点开的详情弹层）在难度标签之后给出缓存齐备信息——
  整本翻译 / 整本朗读 / 全文单词详解各一枚分项小标（哪项备齐亮哪项，悬停显示 `n/m` 与计费口径），
  三项齐备时追加一枚「低成本学习」总标；整本任务面板的三个页签同步挂「已缓存」小标。
- **口径**：判定取本仓三条整本链路的执行台账（`COMPLETED` + 跑满 + 正文指纹一致 + 格式一致），
  不实时探测 moon-well 缓存——详情页是高频读路径，整本探测需解析全书再分批扫缓存。
  标识面向**普通读者**（成本提示），三个整本入口仍只对管理员（R214 拍板①）。
- **非目标**：不做实时缓存探测端点；不改三条整本 job 内核；不在书卡封面另加角标
  （详情弹层已经能看到，先不扩大读路径开销）。
- **验收**：三项齐备亮总标与三枚分项；部分齐备只亮对应分项；换书后指纹变化标识消失；
  从未跑过整本任务的书无标识且页面无报错；普通读者可见、整本入口仍仅管理员。
