# companion 模块（AI 伴读 / Buddy）· 需求基线

> 本文件是 companion 模块的**需求基线**（静态：这个模块「应该」长什么样），随每次需求讨论增改；条目带 `R<编号>` 溯源，被取代的旧条目标注「已被 R<x> 取代」不删除。
> 需求台账见 [`../../project/requests/requests.md`](../../project/requests/requests.md)；用户手册见 [`../readme/companion.md`](../readme/companion.md)；实现说明见 [`features/`](./features/)。
> 建立：2026-10-25（R227 讨论定稿时补建；此前 companion 只有用户手册与 IP 风险登记，R206/R220/R223 的能力只落在台账 + LLD）。

## 1. 模块范围

阅读页与全站的 AI 伴读抽屉、悬浮伙伴按钮、伙伴（buddy）外观系统，以及它们背后的 moon-well 伴读 Agent（`/ai/agent/*`）。

不含：口语陪练 / 写作 / 复述等学习页内的 AI 教练（归 [learning 模块](../learning/requirements.md)）；阅读器本体的排版与翻译（归 [reading 模块](../reading/interface.md)）。

## 2. 需求条目

### moon-well R214 伴读 Agent 按需加载 MagicBook 全功能指南

- **来源**：用户 2026-10-25 原话「把magic book 所有的功能 总结一下，做成一个skill 给 AI伴读的agent使用。先判断AI伴读的agent 是否支持skill」。
- **编号说明**：后端由 moon-well R214 交付；magicbook 本仓的 R214 已被「书籍详情」使用，消费侧文档占 **magicbook R228**。
- **现状判断**：原 AI 伴读 Agent 不支持 Codex / Claude 原生 Skill；moon-well R214 新增的是产品内只读、无脚本、渐进披露的 Skill 机制。

**应该长什么样**：

1. **按需生效**：涉及书库、阅读器、词汇、每日学习、积分、伙伴、账号等具体任务时，助手可加载 MagicBook 全功能指南；普通闲聊不加载。
2. **能导航、不越权**：指南覆盖真实页面、控制项和学习流程，并明确助手不能改设置、点击 UI、开始测验、下单、启动整本任务或管理用户。
3. **费用不臆造**：积分、活动倍率与实时状态以页面或实时接口为准；只有指南明确写出的计费口径才可直接复述。
4. **失败可退化**：指南关闭或不可用时，助手仍可按原提示词和现有工具回答，不得编造功能或假装执行成功。

### R227 Buddy 对话复用口语陪练语音能力（语音输入 + 每条回复朗读）

- **来源**：用户 2026-10-25 原话「我想要 AI 伴读 Buddy 对话也可以复用 AI 口语陪练 陪练的语音能力。」
- **PingCode**：待建（Ship MAGICBOOK 产品 / PJM 迭代 1.0）
- **现状事实**：口语陪练（R221）已有「录音 → ASR 转写 → 确认发送」与「教练语音条」，后端走 `/learning/asr/transcribe` 与 `/tts/speak`；而 Buddy 面板只有文字输入，语音能力仅剩 `synthesize_tts` 工具在模型主动调用时播一段书内朗读。

**应该长什么样**（2026-10-25 四问拍板）：

| 维度 | 口径 |
| --- | --- |
| 语音范围 | **输入 + 朗读双向**：输入框可录音转写；助手回复可朗读 |
| 回复朗读 | **每条手动点「朗读本条」**，不自动播放（回复普遍偏长，自动播既慢又按次计费） |
| 用户语音留痕 | **只转成文字**：不存 MinIO、不渲染可回放语音条，消息仍是纯文本 |
| 生效面 | **全站**（Buddy 自 R220 起是站内助手，任何页面都能说话提问） |

1. **语音输入**：点麦克风开始、再点停止；转写结果**填入输入框**（有草稿则追加），用户可编辑后再发送，**不得自动发送**。
2. **失败可见**：麦克风不可用、录音过短/全静音、ASR 无人声、转写失败都要有明确提示，不得静默。
3. **每条回复可朗读**：助手消息底部提供朗读按钮，点击出声、播放中可再点停止；关抽屉 / 切会话即停。
4. **长回复可听完**：单条回复超过单次合成上限时自动分段连续播放，并显示「朗读中 n/m」。
5. **朗读不改缓存档位**：AI 回复按「AI 临时语音」缓存，不写书籍段落永久缓存。
6. **不因播放放宽安全面**：不得为了播放把 CSP 的 `media-src blob:` 铺到全站。

### R233 AI 回复中的本站链接可直接跳转

- **来源**：用户 2026-10-26 原话「AI给出的本站链接应该可以直接跳转（在新窗口）。」
- **现状事实**：伴读回复由 `renderMarkdown()` 渲染；此前只处理代码、粗体与换行，站内路径和 Markdown 链接都只是纯文本。

**应该长什么样**：

1. **站内可直达**：裸站内路径（如 `/me`、`/credits`、`/book/252`）、当前 origin 的绝对 URL，以及指向这些地址的 Markdown 链接都可点击。
2. **新窗口且隔离 opener**：链接使用新窗口打开，并通过 `rel="noopener noreferrer"` 阻断目标页访问原窗口。
3. **只限站内**：外部域名、协议相对 URL（`//...`）、`javascript:` 等不安全协议与含凭据 URL 一律保持纯文本。
4. **代码不误链**：围栏代码块内原样显示；整段行内代码恰好是站内路径时可点击，其余行内代码仍按代码显示。
5. **标点不入地址**：紧邻链接的中英文句末标点与括号留在链接外，查询参数与 fragment 原样保留。
6. **保持 XSS 边界**：先转义再生成受控标签；链接文字与 `href` 都不得携带未经校验的 HTML。

### R234 悬浮球快捷动作：AI 对话恒在第一位且不可删除（服务端不变量）

- **来源**：用户 2026-10-26 原话「伙伴悬浮球快捷动作，AI 对话始终在第一位切不可删除」。
- **定性**：R223 悬浮球气泡的口径收紧——前端本已做到（chat chip 固定选中不可取消、`renderBubbles` 恒把 chat 排第一位），但服务端 POST 不校验 chat，直连 API 可把 chat 存成缺失或错位；本条把「恒第一位、不可删」升级为服务端不变量。
- **挂靠**：R223（伴读悬浮球）修改意见，不建独立 PingCode idea。

**应该长什么样**：

1. **写入归一**：POST `/ajax/buddy/quick-actions` 一律归一后再落库——chat 缺失自动补到首位、错位自动前移；数量口径连 chat 一起算（4–5 个），发 5 个非 chat 动作＝6 个，拒绝 400 而非静默截断。
2. **读回归一**：GET 与配置读取对存量旧值（R223 期服务端不校验 chat 期间写入的）同样钉首位、截上限；归一后不足 4 个或含白名单外动作则回落默认四项。
3. **前端不动**：气泡渲染、`/buddy` 页 chip 交互行为不变（前端本就恒注入 chat 在首位，服务端归一是双保险）。

### R243 站内信前端：伙伴信封、抽屉 Mail 与独立收件箱

> 2026-10-29 R254 注记：下述第 2、3 条及与“抽屉 Mail 页签”相关的展示/角标口径已被 R254 取代；伙伴信封、独立 `/mail`、统一未读、消息正文与跳转白名单继续有效。

- **来源**：用户 2026-10-28 原话「我想开发一套站内信系统，用以通知用户领取伙伴，领取积分，获得成就 等。伙伴来接受通知，有通知的时候伙伴头上会出现一个信封，用户点击伙伴可以收信。有个专门的【邮件】（站内信）功能。」随后确认：积分通知只覆盖管理员正数发放；成就即时弹层保留；伙伴只是邮差；信中只跳转、不能领取。
- **PingCode**：MB-234 / `tBWd4R5g`，归属 `companion` suite；后端事实与接口由 moon-well R228 交付，本仓 R243 负责消费侧 UI、代理、文案与验收。
- **产品归属与代码边界**：产品入口暂归 companion（伙伴是系统通知的可见邮差），但 magicbook 代码按 `cps/routes/mail.py` 独立域组织；“产品归属 vs 代码模块”拆分作为本轮设计结论，不再单列待拍板项。

**应该长什么样**：

1. **伙伴信封**：存在未读且未解决的邮件时，全站伙伴悬浮头像右上出现信封角标；无未读时消失。角标只是状态展示，`pointer-events:none`，不得新增覆盖伙伴的独立点击层，不得破坏拖拽、hover 快捷气泡、键盘聚焦或原有聊天点击。
2. **点伙伴收信**：抽屉关闭时点击伙伴，有未读则打开 AI 抽屉并停在 `Mail` 页签；无未读则打开原有 `Chat` 页签。抽屉已打开时点击伙伴仍沿用“再次点击关闭”的既有行为。
3. **双页签抽屉**：AI 抽屉提供 `Chat` / `Mail` 两个页签。`Mail` 页签显示最近邮件、未读数、单封展开、全部已读与“查看全部”入口；打开 Mail 页签本身不把邮件标为已读，只有展开单封才标已读。
4. **独立收件箱**：设置菜单新增【邮件】入口，进入完整 `/mail` 页面；按创建时间倒序分页，支持单封展开、全部已读、空态、加载态和错误态。已解决邮件保留历史，但不再产生信封或角标。
5. **统一未读口径**：伙伴信封、设置菜单角标、抽屉 Mail 页签角标与 `/mail` 页面读取同一个未读事实；前端只维护一份 `MBMail` 状态，不做各组件自行计数。
6. **即时反馈**：页面初始化、重新可见/聚焦、打开抽屉 Mail 页签、单封已读和全部已读后刷新未读；不新增轮询 daemon、WebSocket 或后台任务。
7. **失败可见**：未读数或列表接口失败时，抽屉与 `/mail` 显示明确错误与重试入口，不得把接口故障伪装成“没有邮件”。失败后三处未读展示位一律隐藏数字角标并进入“状态不可用”样式；FAB 信封只在最近一次成功计数大于 0 时保留，否则隐藏，不得把未知计数当成 0 或继续展示旧数字。
8. **三类正文**：伙伴可领取、成就解锁、积分到账由 magicbook 按当前 locale 用结构化参数渲染；管理员自定义正文覆盖默认正文，但不得注入 HTML。所有动态值用文本节点渲染。
9. **只跳转不领取**：系统邮件按钮只允许跳 `/buddy`、`/achievements`、`/credits`；R250 运营邮件另允许 `/learning` 与 `/mail`。前端再做一次站内路径白名单校验；不得在邮件内调用领取接口。
10. **管理员积分通知**：积分调整表单新增“同时发送到账通知”和可选纯文本正文；负数调整时禁用并清空通知选项，提交时 `notify=false`。表单仍只调用既有 `/ajax/credit/admin-adjust` 代理，通知字段透传 moon-well。

**边界**：

1. 本仓不创建、不解决、不伪造邮件事实；邮件类型、幂等键、已读/已解决状态全部以 moon-well 为准。
2. 不做邮件删除、回信、附件、富文本、运营群发、模板编辑器、桌面推送或站外通知。
   - **已被 R250 取代**（2026-10-29）：新增管理员运营站内信后台；仍不做富文本、模板编辑器、附件、回信与站外通知，见 §3。
3. 不改成就解锁即时弹层；成就邮件只是持久记录，不能替代弹层。
4. 不改伙伴领取、成就领取、积分账户与流水的既有权限和接口语义。
5. 不新增后台任务、定时器、MQ、daemon 或新的持久化任务表；`/mail` 页面与角标刷新都是请求生命周期内行为。
6. 邮件页和抽屉不缓存邮件正文到 localStorage；退出登录后不得继续显示上一账号的邮件。
7. 登录页、注册页与匿名页面不显示信封、角标或邮件入口。

**验收要点**：

- 有未读时信封出现，点击伙伴进 Mail；无未读时点击伙伴仍进 Chat；聊天快捷气泡始终显式打开 Chat。
- 伙伴拖拽吸附、hover 气泡、键盘聚焦与聊天发送无回归。
- 信封、设置角标、抽屉 Mail 角标与 `/mail` 未读数一致。
- 打开 Mail 页签不标已读，展开单封才标已读；全部已读后三处角标同步消失。
- `/mail` 分页倒序、空态、错误态、重试和跳转可用；已解决邮件保留历史但不计未读。
- 管理员正数调整可勾选通知并填写正文；负数时通知不可用；通知字段透传到 moon-well。
- 所有 `/ajax/mail/*` 代理保持 `_moonwell_proxy` 三元组契约；`read` 的本地参数校验 400 是唯一非三元组分支；接口失败在 UI 可见。
- 新增模板/JS 文案进入 `i18n_seed.html`、zh `.po` 与编译后的 `.mo`，契约测试通过。

**跨仓同源**：moon-well R228（邮件事实、查询、已读/解决、三类投递与管理员 DTO）。

## 3. R250 · 管理员运营站内信后台

> 2026-10-29 R254 注记：本节“抽屉 Mail”现指独立的伙伴邮件弹层；运营邮件的投递、预览、撤回、权限与 `/mail` 展示口径不变。

**来源**：用户 2026-10-29 确认在 R228/R243 基础上开发“管理员自由撰写一封站内信发给一个或多个用户”，拍板：

1. 正文最多 **500 字**。
2. 需要跳转按钮，仅允许站内路径白名单；后台仅管理员可用。
3. 单次发送上限 **5000 人**。
4. 支持撤回。
5. “全体用户”包含管理员本人。

**应该长什么样**：

1. **独立后台** `/admin/mail`：仅 `role_admin()` 可见；提供用户搜索/多选、全体用户、标题、正文、跳转路径、预览与发送。
2. **发送对象**：指定一人或多人，或全体用户；页面显示预计人数；单次上限 5000，服务端再次拒绝超限。
3. **内容**：标题 1–80 字；正文纯文本 1–500 字；可选跳转按钮，路径只允许 `/credits`、`/buddy`、`/achievements`、`/learning`、`/mail`。
4. **发送历史**：显示时间、范围、标题、目标数、成功数、操作人、撤回状态；支持整批撤回与二次确认。
5. **撤回**：按整批撤回；撤回后用户 `/mail` 不再显示、未读数同步下降；发送与撤回审计保留。
6. **用户侧复用**：不新增用户页面；运营邮件在现有 `/mail`、抽屉 Mail、设置入口与伙伴信封中展示。
7. **权限纵深**：页面与代理先查 `role_admin()`；moon-well 再按 `credit.admin-user-ids` 白名单校验。
8. **失败可见**：人数超限、内容非法、非管理员、上游失败、撤回失败都必须明确提示，不得静默成功或截断。

**边界**：

1. 不做草稿、定时发送、富文本、模板编辑器、附件、回信、外部邮件、打开率或点击率统计。
2. 撤回只支持整批，不支持单封撤回；撤回后不可恢复。
3. 不在浏览器保存邮件正文或用户名单到 localStorage。
4. 不改变现有系统事件邮件的投递、已读与解决语义。
5. 不新增用户侧邮件页面或第二套未读状态。

**验收要点**：

- 非管理员看不到入口，直连五个代理均 403 且不调用上游。
- 指定一人、多人、全体用户均可发送；重复用户去重；5001 人拒绝。
- 标题/正文/路径边界正确；外链不生成按钮。
- 发送后用户收件箱出现运营邮件；预览、历史、撤回可用。
- 撤回后用户收件箱与未读数同步；审计保留。
- 运营邮件按纯文本渲染，不使用 `innerHTML` 拼接服务端数据。

**跨仓同源**：moon-well R230（`ADMIN_ANNOUNCEMENT`、群发审计、整批撤回）。

## 4. R254 · 伙伴邮件弹层与 AI 对话抽屉分离

**来源**：用户 2026-10-29 原话「邮件不要出现在AI伴读对话框中。当新邮件到达的时候，点击伙伴弹框显示邮件而不是跟AI伴读公用一个弹框」。

**应该长什么样**：

1. **AI 抽屉只负责对话**：AI 伴读抽屉不再包含 Mail 页签、邮件列表或任何邮件 DOM，只保留 Chat、会话工具与记忆面板。
2. **独立邮件弹层**：新增伙伴邮件弹层，展示最近 5 封、统一未读数、全部已读和“查看全部”；桌面为右下浮层，移动端为全屏层。
3. **FAB 分流**：无伙伴浮层打开时，点击伙伴有未读进入邮件弹层、无未读进入 AI 对话；邮件弹层或 AI 抽屉已打开时，再点伙伴关闭当前浮层。
4. **快捷气泡不误分流**：悬停快捷气泡“对话”始终显式打开 AI 对话，不受未读状态影响。
5. **互斥与状态**：邮件弹层与 AI 抽屉不得同时出现；打开邮件弹层不自动已读，展开单封才调用已读接口。
6. **保留既有入口**：设置菜单【邮件】、完整 `/mail`、FAB 信封、伙伴隐藏后的唤回提示与统一 `MBMail` 未读状态均保留。
7. **匿名隔离**：登录页、注册页与匿名阅读不渲染邮件弹层、FAB 信封或邮件入口。

**边界**：

- 不改 moon-well 邮件事实、查询、已读/解决接口与运营邮件契约。
- 不新增轮询、WebSocket、后台任务或第二套未读状态。
- 不在 localStorage/sessionStorage 缓存邮件正文；不扩大邮件跳转白名单。

**验收要点**：

- AI 抽屉 DOM 中不存在 Mail tab、Mail pane 或邮件列表。

- 打开弹层不标已读，展开单封才标已读；全部已读后 FAB、设置角标、弹层和 `/mail` 同步。
- 匿名页面不渲染弹层；登录态布局、三种阅读器、`/mail`、管理员运营发信回归无失败。
