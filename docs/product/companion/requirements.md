## 1. 模块范围

阅读页与全站的 AI 伴读抽屉、悬浮伙伴按钮、伙伴（buddy）外观系统，以及它们背后的 moon-well 伴读 Agent（`/ai/agent/*`）。

不含：口语陪练 / 写作 / 复述等学习页内的 AI 教练（归 [learning 模块](../learning/requirements.md)）；阅读器本体的排版与翻译（归 [reading 模块](../reading/interface.md)）。

## 2. 需求条目

### R227 Buddy 对话复用口语陪练语音能力（语音输入 + 每条回复朗读）

- **来源**：用户 2026-10-25 原话「我想要 AI 伴读 Buddy 对话也可以复用 AI 口语陪练 陪练的语音能力。」
- **PingCode**：待建（Ship MAGICBOOK 产品 / PJM 迭代 1.0）
- **现状事实**：口语陪练（R221）已有「录音 → ASR 转写 → 确认发送」与「教练语音条」，后端走 `/learning/asr/transcribe` 与 `/tts/speak`；而 Buddy 面板只有文字输入，语音能力仅剩 `synthesize_tts` 工具在模型主动调用时播一段书内朗读。

**应该长什么样**（2026-10-25 四问拍板）：

| 维度 | 口径 |
| --- | --- |
| 语音范围 | **输入 + 朗读双向**：输入框可录音转写；助手回复可朗读 |
| 回复朗读 | **每条手动点「朗读本条」**，不自动播放（回复普遍偏长，自动播既慢又按次计费） |
| 用户语音留痕 | **只转成文字**：不存 MinIO、不渲染可回放语音条，消息仍是纯文本 |
| 生效面 | **全站**（Buddy 自 R220 起是站内助手，任何页面都能说话提问） |

1. **语音输入**：点麦克风开始、再点停止；转写结果**填入输入框**（有草稿则追加），用户可编辑后再发送，**不得自动发送**。
2. **失败可见**：麦克风不可用、录音过短/全静音、ASR 无人声、转写失败都要有明确提示，不得静默。
3. **每条回复可朗读**：助手消息底部提供朗读按钮，点击出声、播放中可再点停止；关抽屉 / 切会话即停。
4. **长回复可听完**：单条回复超过单次合成上限时自动分段连续播放，并显示「朗读中 n/m」。
5. **朗读不改缓存档位**：AI 回复按「AI 临时语音」缓存，不写书籍段落永久缓存。
6. **不因播放放宽安全面**：不得为了播放把 CSP 的 `media-src blob:` 铺到全站。
