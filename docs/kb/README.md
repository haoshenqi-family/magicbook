# 知识库（docs/kb）

放**跨需求长期有效的事实**：踩过的坑、工具用法、不可从代码直接看出的约定。
与 `docs/product`（产品语义）、`docs/project`（某次迭代的交付物）区分开——
这里的文档不随迭代结束而失效。

| 路径 | 内容 |

## 写法约定

- 每篇开头写「为什么建这篇」——没写清起因的知识库，半年后没人敢删也没人敢信。
- 数字、路径、命令都写实测值，不写「大约」「一般来说」。实测不了的就标「未核实」。
- 结论性判断要给触发条件（「什么时候该重新评估」），否则会变成永久性的错误共识。
